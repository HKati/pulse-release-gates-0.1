## New minimal invocation

This is a **new phase-specific profile**, not a relaxed historical bootstrap
request. Existing `prepare_containment()` materializes the whole selected
bootstrap view; it cannot describe this minimal entry-only view unchanged.
Keep its request/schema and the old one-tracee task guard intact.

The new trusted startup helper is the pre-exec phase of task L. It prepares an
exact FD table, remains behind an owned barrier, installs the new task guard
under observation, and executes the original launcher through its sealed ELF
descriptor. No shell, intermediate helper process or arbitrary caller program
is allowed.

| Initial FD | Bound role |
| ---: | --- |
| 0 | Independent empty sealed input. |
| 1, 2 | Separate bounded stdout and stderr pipe write ends. |
| 3 | Sealed argument bytes, inherited into initial launcher exec. |
| 4 | Sealed exact static-entry bytes, inherited into initial launcher exec. |
| 5 | Sealed exact containment BPF, inherited into initial launcher exec. |
| 6 | Sealed original launcher ELF, `CLOEXEC`; `execveat(..., AT_EMPTY_PATH)` target. |
| 7 | Owned helper barrier, `CLOEXEC`; only the fixed release token is accepted. |

Bind all seals, bytes, ownership, open-file identities and inheritance flags
before release. Descriptor integers can be reused after a role closes; an equal
number never proves continuous identity. The helper's code/build/source binding,
guard-installation witness and parent-loss behavior are implementation gates.

Launcher argv is exactly `['bubblewrap', '--args', '3']`, cwd `/`, environment
`LC_ALL=C` and `TZ=UTC`. FD 3 contains the following tokens, each followed by one
NUL byte. The layout below is explanatory; it is not a command to execute:

```text
--unshare-user
--unshare-ipc
--unshare-pid
--unshare-net
--unshare-uts
--unshare-cgroup
--disable-userns
--cap-drop ALL
--die-with-parent
--clearenv
--setenv LC_ALL C
--setenv TZ UTC
--perms 0700 --tmpfs /
--perms 0700 --dir /empty
--perms 0700 --dir /runtime

```

Every permissions setting applies to its next filesystem operation. The exact
view is four directories and one regular executable file. No `/proc`, `/dev`,
host-directory bind, Python capsule or other payload is mounted in that view.
There are no `--try` options, external namespace FDs, `--as-pid-1`, sync/lock/status
options, caller-selected phase, or fallback executable.

At T's terminal entry stop, expect `LC_ALL=C`, `TZ=UTC`, **and `PWD=/empty`**;
bubblewrap adds PWD. The static entry's later two-variable environment replacement
has not happened. The fixed `worker` argument does not mean the worker ran.

## Three roles and exactly two subject births

| Role | Real-parent relationship before cleanup | Responsibility |
| --- | --- | --- |
| L | Direct child of outer observer | Trusted pre-exec helper becomes original bwrap monitor in the same task. |
| R | Created by L | Namespace setup becomes namespace PID 1 / reaper. |
| T | Created by R | Payload executes the exact static entry and stops before user instructions. |

The outer observer is not counted among these three tasks. Runtime PID, TID,
start time, pidfd, namespace identities and child-TID addresses must be acquired
and joined during that attempt, never filled from a prior run or an invented PID.

| Birth | Linux x86-64 syscall | Exact flags | Argument qualification |
| --- | --- | --- | --- |
| L to R | `clone` 56 | `0x7e020011` | `NEWNS|NEWUSER|NEWPID|NEWNET|NEWIPC|NEWUTS|NEWCGROUP|SIGCHLD`; null child stack. |
| R to T | `clone` 56, through glibc `fork()` | `0x01200011` | `CHILD_SETTID|CHILD_CLEARTID|SIGCHLD`; null stack and dynamically bound child-TID/TLS address. |

The first `raw_clone()` supplies only two variadic arguments. Unused trailing
syscall registers must not be required to equal zero. For the second call, bind
the actual ABI-relevant argument semantics rather than guessing its address.
Both selected calls use SIGCHLD, so the expected ptrace birth notification is
`PTRACE_EVENT_FORK`, even though the syscall is named clone.

The new guard rejects raw `fork`, `vfork`, `clone3`, other clone masks, x32 and
task-creation bypasses. The observer additionally checks the caller role, order,
occurrence count and relevant arguments **before** releasing a creation syscall.
Permitting two masks alone is insufficient. In particular, `CLONE_UNTRACED`,
`CLONE_THREAD`, `CLONE_PARENT` and `CLONE_VFORK` are outside this contract.

These relationships derive from the original bubblewrap source at
`bubblewrap.c:3017-3075,3439-3471`, `utils.c:888-897`, and the selected glibc
fork chain. Exact members and their hashes are in the source inventory. They are
source expectations; the selected host still has to demonstrate them.

## Required observation sequence

The observer must be a verified child subreaper before L exists, with normal
SIGCHLD disposition, no `SA_NOCLDWAIT`, and no competing wait consumer. Preserve
its original setting and restore it only after complete cleanup. A private
startup barrier fails closed on EOF, an invalid token or observer loss.

Use the new `PTRACE_SEIZE`/`PTRACE_INTERRUPT` contract, with option mask
`0x0010001f`: `TRACESYSGOOD`, `TRACEFORK`, `TRACEVFORK`, `TRACECLONE`, `TRACEEXEC`,
and `EXITKILL`. Deliberately exclude `TRACEEXIT`, `TRACESECCOMP`, and
`SUSPEND_SECCOMP`. SEIZE alone does not stop the task. Consume and validate the
interrupt stop before releasing the helper. Do not reattach automatically traced
children or issue INTERRUPT blindly to an already stopped role.

| Checkpoint | Required evidence before further execution |
| --- | --- |
| L helper barrier | Exact helper identity, complete FD table, seals, parent relation and consumed stop before releasing the fixed barrier. |
| L guarded pre-exec phase | Observe the exact new task-guard submission and successful return before permitting launcher exec. |
| L initial launcher exec stop | Original launcher and kernel-interpreter identity, exact exec event and selected input continuity. This is not yet the full native map. |
| L stopped before first namespace clone | Separate fresh complete selected-native mapping/backing roster, source/input admission and exact clone arguments. |

| R setup and R to T birth | Namespace transitions, mount/view operations, exact second clone, newborn identity and complete owned-role ledger. |

Keep newborn T stopped while R reaches its verified reaper park. L must release
R's startup barrier before parking. Maintain explicit running/stopped state for
each role and record every syscall, wait event, signal and restart. Unexpected
task creation, exec, mapping, event or unsupported state makes the attempt
incomplete before further subject execution. Never extend a selected roster to
fit an observed result.

The changed `--args` invocation must supply its own live L observations. The
historical nine-return capture, its old guard and its two-slot qualification do
not admit this new profile. Mapping/backing identity in the new prefix must not
be described as nine newly observed consumer/provider returns or continuous
whole-runtime consumption coverage. Those broader occurrence obligations remain
open unless separately witnessed by a later reviewed collector.

The collector may read task state and control reviewed stops. It must not patch
instructions, memory or registers, replace syscall results, detach a task, or
substitute a scripted response for a native record. The independent checker
reconstructs the request and raw state; the producer's success field is not proof.

## What the terminal evidence must establish

### Namespace and process relationships

Bind final T and R namespace handles, UID/GID maps and task identities for user,
mount, PID, IPC, network, UTS and cgroup namespaces. The intended R/T relationships
are distinct from L's external monitor role. Do not impose final payload state on
L or use namespace inode inequality as the entire proof.

`--disable-userns` creates a second user namespace. Bubblewrap's early reported
namespace IDs precede that transition and cannot identify final payload state.
Record the actual selected transition and its additional-userns denial check;
one denied call is not proof of every possible future call. Namespace-relative
capabilities during setup are distinct from final T credentials. Require the
declared terminal zero capability fields and `NoNewPrivs=1` from task-bound data,
without claiming the static entry checked them itself.

### Exact readonly root, executable and descriptors

Retain raw task-bound mountinfo and interpret **effective per-mount VFS readonly
flags**. A tmpfs superblock reporting `rw` does not by itself mean an effective
bind/root mount is writable. Independently walk a pinned T root and require the
entire declared path/type/mode/byte roster, root/cwd identity and executable
binding. Reject unexpected mounts, aliases, symlinks, writable paths or files.

`--ro-bind-data` copies its sealed input into a temporary file, sets its mode,
binds it readonly and unlinks the temporary name. The resulting executable is
not the input memfd's inode and need not carry memfd seals. Bind the sealed source
bytes, copied readonly file, actual exec image and read-only view as distinct
relations. Do not equate two different file objects by filename alone.

T's terminal descriptor roster must be exactly **0, 1, 2**, with declared stdio
identities. The helper's launcher FD is CLOEXEC; bubblewrap consumes/closes its
argument, entry-source and seccomp FDs; its internal proc FD closes before payload
exec; lifecycle eventfds are CLOEXEC. L and R retain their separately declared
monitoring/reaping FDs. Source behavior is not sufficient: `fdwalk()` can return
when its proc FD enumeration fails, so missing or extra descriptor evidence is
fatal to this profile. T's own `close_range()` is still unexecuted.

### Two separate selected-filter installations

The selected source applies the containment BPF in **R's `do_init()`** and again
in **T before payload exec**. Both applications occur after R forked T. R's
installation therefore cannot be treated as inherited by that already-existing
child.

For each role independently, retain the task-bound syscall-entry record,
`sock_fprog` and exact BPF bytes, their continuity across the submission,
successful return, and appropriate filter-state transition/inheritance. The
new startup task guard and this later containment policy are separate layers.
`Seccomp=2` or a filter count alone cannot identify either exact program.

Report **observed selected-program submission**, under the declared observer and
kernel trust. Do not label it privileged kernel filter readback or exhaustive
proof of all later syscall prohibitions. The existing bootstrap BPF permits
`wait4`; this reaper path needs no relaxation of that policy.

### Static entry has not run

At the terminal exec stop, the entry's first instruction is pending. Its own
capability/NNP/seccomp checks, `close_range(3, ...)`, CPU/AS/CORE/FSIZE/NOFILE limits,
environment replacement and selected-loader exec have not happened. Keep each
execution claim false even when outer observations show a similar state.

The narrow future success claim is: the exact entry was reached at its initial
exec stop with the specified independently reconstructed containment-state
relations. It is not whole-interval authentication, a completed bootstrap,
source/binary equivalence, a property measurement or a release decision.

## Terminal cleanup and incomplete attempts

After the terminal snapshot, permit read-only collection and direct
`pidfd_send_signal(owned_pidfd, SIGKILL, NULL, 0)` in T, R, L order. Do not use
`PTRACE_CONT(..., SIGKILL)`, `PTRACE_KILL`, DETACH, LISTEN, SYSCALL, CONT, SINGLESTEP
or SYSEMU on T after its terminal event. No T restart is needed or allowed.

The all-stopped condition describes the successful terminal checkpoint, not a
precondition for failure cleanup. On an incomplete prefix, signal and drain only
identities actually created and owned, in reverse role order. Do not wait for
absent roles or require surviving tasks to reach intended stops before SIGKILL.
Missing final-removal proof keeps that attempt incomplete.

Drain owned tracing, adoption and final-reaping notifications globally within the
cleanup deadline. Do not wait exclusively for R while neglecting T: PID-namespace
teardown can wait for externally traced children to be released. A tracer's
terminal notification can leave a zombie for its real parent, so **exactly three
wait results is not a valid completion rule**.

Require every owned task's consumed termination state, qualified final pidfd
hangup/removal evidence, and a drained owned wait ledger. Pidfd readability can
indicate a zombie; `WNOHANG=0`, an isolated ESRCH or successful SIGKILL submission
does not prove final removal. Never signal a recycled numeric PID or a stale
process group. Preserve both the primary failure and cleanup failures.

These are proposed requirements, grounded in reviewed
[ptrace interrupt handling](https://github.com/torvalds/linux/blob/v6.12/kernel/ptrace.c#L1106-L1130),
[tracer/real-parent exit handling](https://github.com/torvalds/linux/blob/v6.12/kernel/exit.c#L1164-L1250),
[PID-namespace teardown](https://github.com/torvalds/linux/blob/v6.12/kernel/pid_namespace.c#L170-L253)
and [pidfd polling](https://github.com/torvalds/linux/blob/v6.12/fs/pidfs.c#L95-L114).
Linux v6.12 here is a reference source, **not the selected future host kernel**.
Every relied-upon tracing, signaling and removal behavior requires qualification
on the exact selected host. EXITKILL after observer loss does not create a
completed verification report.

Store events in bounded sequential streams; a trace event is not a separate file.
The evidence schema must account for every required member within these caps.
Overflow, truncation, timeout or interrupted cleanup leaves a preserved incomplete
attempt. Increasing a cap requires a separately reviewed selection; no automatic
retry or growth is permitted.

Before any original attempt, the new implementation must establish fresh original
and explicit-policy admission, complete helper provenance, a separately tested
multi-task guard, and same-observer/same-host authored qualification. Qualify
nonroot equal real/effective IDs, the non-setuid launcher, required namespace and
mount operations, openat2, inherited tracing, proc/register/memory access through
user-namespace transitions, both policy submissions, and cleanup.

Bind the exact kernel, image, observer environment and any outer seccomp/AppArmor
policy. The existing Docker cap-drop/no-new-privileges/default-security selection
does not establish that the new namespace setup is supported. Denial of an
operation required to succeed is an incomplete result. Preserve the explicitly
expected negative checks, including additional user-namespace creation denial;
do not automatically enable privileged/unconfined execution,
change host sysctls, weaken the namespaces or switch observer backends.

## Selected bootstrap remains a separate integration

The historical original-input archive contains an **authored example runtime**:
`capsule/authored-runtime-capsule.zip` is 219,962 bytes, and its
`python/bin/python3.11` payload is a 1,056-byte authored ELF. The associated
runtime, operator, bootstrap and containment selections are `record_status=example`.
Their exact identities are recorded in the source inventory. They cannot become
real selected CPython by relabelling, rehashing, or passing the original-loader
observation.

The minimal containment-entry profile does not require that Python capsule. The
later bootstrap unit does require a **new real capsule**, selected before its
execution:

| Required new input | Acceptance requirement |
| --- | --- |
| Interpreter and environment | Actual selected CPython 3.11.16, Linux x86-64, Unicode 14.0.0 under the current v0 contract; exact executable and original-source/trust bindings. |
| Runtime and operator selection | Fresh `selected` runtime and `observed` operator selections bound to the same actual repository commit and environment, with selected source bytes checked against Git objects. These status labels do not themselves authenticate execution. |
| Recoverable closed files | Every file, path, role, size, hash and origin; package metadata, licenses, module/resource providers and independent capsule identity. |
| Native dependencies | Every declared ELF object's `PT_INTERP` and `DT_NEEDED` edges, including interpreter, loader, extensions and shared libraries; unambiguous providers, permitted loader aliases and exact view paths. Static relationships are not actual consumption evidence. |
| Probe obligations | Independently selected source/extension or builtin/frozen provider for each module; exact schema-resource relations; real-interpreter declarations rather than copied fixture declarations. |
| Budgets and formats | Measure the complete real inventory against existing v0 caps before deciding whether that version fits. No silent omission or widening. |

The current runtime caps include 4,096 payload files, 128 MiB per payload,
256 MiB total decoded ZIP including controls, and 384 MiB archive bytes. The
bootstrap view permits 8,192 files / 512 MiB. These do not prove that a real
candidate fits. Runtime ZIPs and the final view also have strict path, alias,
metadata and startup-file rules; see
[runtime preservation](PULSEMECH_REQUIRED_GATE_IDEMPOTENCE_RUNTIME_v0.md) and
[bootstrap preparation](PULSEMECH_REQUIRED_GATE_IDEMPOTENCE_BOOTSTRAP_v0.md).

A real selection may use the existing v0 contract if it satisfies every version,
path, format and bound unchanged. A changed contract needs a distinct reviewed
profile/version with matching producer, checker, schema, tests and source
inventory. Do not relax old pinned schemas to make new inputs pass.

The ordered later boundaries are:

1. Admit and preserve the new actual runtime/operator capsule without execution.
2. Define a separate selected-loader exec stop after the static entry has run its
   own checks, FD closure, limits and environment replacement.
3. Define separate finite worker and collector **bootstrap diagnostic** runs with
   outer observations and independent replay. Probe imports/self-report do not
   prove complete transitive runtime closure or actual acquisition.
4. Design actual worker FD/task/exec/input-consumption integration. The current
   static entry closes all FDs above 2, the view lacks `/proc`, and its filter
   forbids task creation. The real process primitive needs sealed worker/request/
   input FDs, `/proc/self/fd/<workerFD>` and new worker processes. These contracts
   cannot be connected by merely removing the selected-execution guard.
5. Only then address the separately selected 24 property applications and B3/B4/B5
   obligations. The bootstrap probe itself performs zero property applications
   and zero model calls.

Keep `selected_bootstrap_execution_not_ready`, the example/selected checker
restrictions and `observed_acquisition_not_ready` unchanged in this unit.
The historical Q2 result, twelve unsupported gates and broader Step 5C/5D,
resource and promotion obligations retain their meanings.
